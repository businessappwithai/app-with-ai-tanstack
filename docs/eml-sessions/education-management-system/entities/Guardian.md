# Guardian  ·  standalone  ·  category: People

**Role.** The adult legally responsible for one or more students. Not a parent field on the student, because step-parents, carers and local authorities all appear here and only one of them is the primary contact.

**Placement.** Standalone. Two students sharing a guardian share this record — which is the whole reason a guardian is not a set of columns on the student.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `email` | email | UK | The address invoices, offers and absence notifications are sent to. Unique — two students sharing a guardian share this record, which is the whole point of guardians being their own entity. |
| `first_name` | string | — | Given name, as it should appear on correspondence. |
| `last_name` | string | — | Family name. Often differs from the student's, which is exactly why it is held here rather than assumed. |
| `phone` | phone | — | The number the school calls when a child is ill or has not arrived. The single most important field in a safeguarding emergency. |
| `address_line` | string | — | The billing and correspondence address. A student's home address is the primary contact's, which is why it lives here. |
| `city` | string | — | Town or city, used for transport route planning and catchment reporting. |
| `postcode` | string | — | Postal code — the field the catchment and transport reports actually group by. |
| `preferred_contact_method` | string | — | email — the default and the only one that scales; phone — reserved for guardians who ask, and used for every emergency regardless; post — required where a guardian has no email, and it slows every notice by three days. |
