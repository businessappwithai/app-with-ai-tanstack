# Enrollment  ·  standalone  ·  category: Enrolment

**Role.** One student's place in one section for one term. Created when the registrar places the student; terminal once completed, withdrawn or failed.

**Placement.** Standalone. The registrar's working list is enrolments across sections, not a tab on one section.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `student_id` | string | FK | The student holding the place. An enrolment is never transferred between students; a change of group is a withdrawal and a new enrolment, so the attendance and marking trail stays attached to the right child. |
| `class_section_id` | string | FK | The taught group the place is in. With the section's day and period this is what a timetable clash is detected on. |
| `status` | string | — | pending — requested, not yet placed by the registrar; enrolled — holding a place and expected at every session; completed — the term ended with a final grade; withdrawn — left the group during the term, and the reason is required; failed — completed without meeting the pass standard. |
| `enrolled_on` | date | — | When the place was taken. Compared against the term's census date to decide whether the term is billable, which is why it is a date the registrar may not backdate freely. |
| `withdrawn_on` | date | OPTIONAL | When the student left the group. The fee is not automatically adjusted — a withdrawal after census is still billed, and this date is the evidence in that conversation. |
| `withdrawal_reason` | text | OPTIONAL | Why the student left the group — timetable clash, subject change, medical, exclusion. Required on withdrawal, and the subject-change reports are built entirely from it. |
| `final_grade` | string | OPTIONAL | distinction, merit, pass, borderline, fail — the outcome recorded when the section completes; incomplete — the student left or missed too much of the course to be graded. Written once at term end and never edited afterwards; a correction is a documented re-grade. |
| `attendance_rate` | decimal | — | The percentage of held sessions this student was present for, maintained by the attendance hook as marks are entered. Held on the enrolment rather than computed because it is the number the pastoral team sorts by every week, and the statutory floor is measured against it. |

## Rules

### `enrolmentControl` on `beforeUpdate` — **`%%action` decision table — it can act**

- `requireEnrolmentWithdrawalReason validation-error when: status == "withdrawn" and withdrawal_reason == null message: A student leaving a group needs a reason — the subject-change reports are built from it.`
- `refuseGradeBeforeCompletion validation-error when: status == "pending" and final_grade != null message: A final grade cannot be recorded on an enrolment that has not been placed yet.`
- `requireGradeOnCompletion validation-error when: status == "completed" and final_grade == null message: A completed enrolment needs a final grade.`

## Cross-entity effects

Creating an enrolment increments the section's counter (`incrementSectionEnrolment`); changing its status maintains it (`maintainSectionEnrolment`). Capacity is checked in the `checkSectionCapacity` handler and **not** as a rule — §10.4's second route: the condition names a fact about the section, which a `when:` cannot read, so a rule written that way would have been seeded, drawn by the viewers, and inert.

Sagas that touch it:

- **SectionCancellation**
