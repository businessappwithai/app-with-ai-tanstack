# AssessmentResult  ·  child of Assessment

**Role.** One student's mark for one assessment. Created when the assessment is published to the group and scored when it is marked.

**Placement.** Child of `Assessment`.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `assessment_id` | string | FK | The piece of work being marked. This is the link back to the parent record, so results appear as a tab on the assessment. |
| `student_id` | string | FK | Whose work it is. One result per student per assessment. |
| `marked_by_id` | string | FK OPTIONAL | Who marked it. Usually the section's teacher, but a moderated or second-marked paper carries the moderator, and that is what makes the moderation trail auditable. |
| `score` | decimal | OPTIONAL | The mark awarded, on the scale max_score sets. Blank until marked — a blank is not a zero, and the reports keep the two apart deliberately. |
| `max_score` | decimal | — | The paper's maximum as it stood when this result was created, copied from the assessment. Held here for the same reason an invoice line keeps its price: a paper rescaled next year must not rewrite marks already awarded, and the score rule compares against this rather than against the assessment. |
| `status` | string | — | pending — published, nothing submitted yet; submitted — work is in, not marked; marked — a score is recorded; missing — nothing was submitted and the deadline passed, which counts as zero in the weighting; excused — the student was authorised not to sit it, and it is removed from the weighting rather than counted as zero. |
| `marked_at` | datetime | OPTIONAL | When the mark was recorded. The turnaround report is the gap between this and the assessment's due date, and it is the number departments are held to. |
| `feedback` | text | OPTIONAL | What the student is told about the work. The one field in the model written to be read by a child, so it is never a grade restated as a sentence. |

## Enums

- `status` → **ResultStatus**: pending, submitted, marked, missing, excused

## Rules

### `markingControl` on `beforeUpdate` — **`%%action` decision table — it can act**

- `refuseScoreAboveMaximum validation-error when: score > max_score message: A score cannot exceed the paper's maximum as it stood when the result was created.`
- `refuseNegativeScore validation-error when: score < 0 message: A score cannot be negative. A missing piece of work is the missing status, not a negative mark.`
- `requireScoreWhenMarked validation-error when: status == "marked" and score == null message: A marked result needs a score. A blank is not a zero and the reports keep the two apart.`

## Hooks

- `beforeCreate` → `copyAssessmentMaximum`
- `afterUpdate` → `stampMarkedAt`

## Cross-entity effects

None outward. Inward: `copyAssessmentMaximum` stamps `max_score` from the paper at creation — the §10.4 first route, a column that earns its place, and the reason `refuseScoreAboveMaximum` can be a rule at all.
