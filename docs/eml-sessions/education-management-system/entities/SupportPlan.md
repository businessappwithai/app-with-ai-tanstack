# SupportPlan  ·  standalone  ·  category: Student Support

**Role.** The controlled summary of a student's learning, accessibility, medical or behaviour support, its accountable owner and scheduled review. Teachers receive the adjustments they need without broad access to sensitive evidence.

**Placement.** Standalone. The counsellor's caseload — active plans ordered by review date (`counsellor-support-reviews-due`) — is a list opened away from any one student, and a plan has an accountable owner (`owner_id`, a `Staff` reference).

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `student_id` | string | FK | The student receiving support. One student may have separate plans for learning, accessibility, medical needs or behaviour. |
| `owner_id` | string | FK | The member of staff accountable for coordinating the plan, arranging reviews and confirming that agreed adjustments reach teachers. |
| `plan_type` | string | — | The primary support domain, used to route the plan to the right specialist without exposing it to unrelated roles. |
| `status` | string | — | draft — being agreed; active — adjustments apply now; under_review — outcomes and needs are being reassessed; closed — no longer in force but retained for continuity and audit. |
| `starts_on` | date | — | The date the agreed adjustments begin. Staff should not apply a draft plan before this date. |
| `review_due_on` | date | — | The next date the owner must review outcomes, needs and adjustments with the student and guardian as appropriate. |
| `closed_on` | date | OPTIONAL | When support under this plan ended. Required when the plan is closed so historic decisions have a clear boundary. |
| `needs_summary` | text | — | A concise functional description of what affects learning, access, health or behaviour. Record only what staff need to support the student. |
| `adjustments` | text | — | The practical changes staff must make in lessons, assessment, access or care; written so a teacher can act without reading sensitive background evidence. |
| `review_notes` | text | OPTIONAL | The latest review outcome, including what worked, what changed and who was consulted. Earlier versions remain in the generated audit history. |
| `active_at` | datetime | OPTIONAL | When the move to active was recorded on this support plan. Recording it moves a support plan from draft or under review to active: the workflows set the status, which nobody changes by hand. |
| `under_review_at` | datetime | OPTIONAL | When the move to under review was recorded on this support plan. Recording it moves a support plan from active to under review: the workflows set the status, which nobody changes by hand. |
| `closed_at` | datetime | OPTIONAL | When the move to closed was recorded on this support plan. Recording it moves a support plan from active or under review to closed: the workflows set the status, which nobody changes by hand. |

## Cross-entity effects

Keeps `Student.has_support_plan` true while the student has a plan that is `active` or `under_review`: `syncStudentSupportFlagOnCreate`, `…OnUpdate` and `…OnDelete` recompute the flag from the student's plans after each write, so a draft or closed plan does not set it and closing the last live plan clears it.

Sagas that touch it:

- **SupportPlanActiveMove** *(triggered on this entity)*
  - `B UpdateEntity field: status value: active`

  - `C UpdateEntity field: active_at value: null`

## Open questions

Teachers read the plan (`adjustments`) without being able to create or change it, which is the intent of the entity's help text: the adjustments they need, without broad access to sensitive evidence. A student with two plans keeps the flag until the last live one closes.
