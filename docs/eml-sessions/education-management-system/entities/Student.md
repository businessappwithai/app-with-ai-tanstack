# Student  ·  standalone  ·  category: People

**Role.** The child. Created when an offer is accepted, never at enquiry, and never deleted — a leaver is a status, because safeguarding and alumni obligations both need the record to survive.

**Placement.** Standalone, and the central artefact of the model.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `student_number` | string | UK | The school's own identifier, unique and unchanging for the child's whole time here. Printed on every report, invoice and examination entry. |
| `first_name` | string | — | Given name as it should appear on a certificate. A preferred name is not held separately — the school records the legal name and staff use it. |
| `last_name` | string | — | Family name. Registers and result lists sort by it. |
| `date_of_birth` | date | — | Used to derive the year group at admission and to check examination-board age rules. Never changed after admission except to correct a keying error. |
| `year_group` | integer | — | The teaching year the student is in, 7 to 13. Advanced once a year at rollover; a repeated year is an explicit edit, and the reason belongs in a conduct or pastoral record rather than here. |
| `status` | string | — | enrolled — attending and fee-liable; on_leave — place held for a term abroad or extended illness; suspended — a conduct outcome, still enrolled and still fee-liable but barred from sessions; graduated — completed year 13; withdrawn — left before completing, and the reason is required. |
| `enrolled_on` | date | — | The date the offer was accepted and the record created. The fee position, the year group and the alumni record are all measured from it. |
| `withdrawn_on` | date | OPTIONAL | The date the student left. Set with the status; the term's invoice is not cancelled by it, which is what makes the leavers report a finance report as well as a registry one. |
| `withdrawal_reason` | text | OPTIONAL | Why the student left, in the family's terms — relocation, transfer, financial, exclusion. Required on withdrawal, because the retention report is built from it and an unexplained leaver is the one the governors ask about. |
| `school_email` | email | OPTIONAL | The account the student signs in with. Optional: it is issued at year 7 and some transfers arrive without one. |
| `has_support_plan` | boolean | — | Set when the student has a formal learning-support plan. It is a flag, not the plan: the plan itself is held outside this system, and this field exists so a teacher opening the register knows to ask for it. |

## Cross-entity effects

Suspension is written **onto** the student by the `SuspensionEscalation` saga when a conduct record records a suspension sanction — trigger `DisciplineIncident` → target `Student` → transition `enrolled|on_leave → suspended`. Withdrawal deliberately does *not* cascade: the term's invoice stands, which is the school's policy and the reason `Enrollment.withdrawn_on` is evidence rather than a trigger.

Sagas that touch it:

- **AdmissionToEnrolment**
  - `B CreateEntity entity: Student as: newStudentId fields: {"first_name":"applicant_first_name","last_name":"applicant_last_name","date_of_birth":"applicant_date_of_birth","year_group":"year_group_applied_for","status":"enrolled","has_support_plan":false}`
  - `C UpdateEntity field: student_id source: newStudentId`
  - `D CreateEntity entity: FeeInvoice as: newInvoiceId fields: {"student_id":"newStudentId","academic_term_id":"academic_term_id","status":"draft","total_amount":0,"amount_paid":0,"balance_due":0}`
- **SuspensionEscalation**
  - `B UpdateEntity entity: Student targetField: student_id field: status value: suspended`
