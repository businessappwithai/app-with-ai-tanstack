# Assessment  ·  standalone  ·  category: Assessment

**Role.** A marked piece of work set on a section — a quiz, an essay, a mock exam — with a maximum score, a weight and a due date.

**Placement.** Standalone. A teacher's "what have I got to mark" spans every section they teach.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `class_section_id` | string | FK | The taught group the work is set on. Every student enrolled in the section gets a result row when the assessment is published. |
| `title` | string | — | What the work is called, as it appears in the student's list, e.g. "Unit 3 test — forces". |
| `assessment_type` | string | — | quiz — short, low weight; essay — extended writing; project — coursework over weeks; practical — laboratory or performance; mock_exam — full paper under examination conditions; final_exam — the summative paper the term's grade rests on. |
| `max_score` | decimal | — | The maximum mark available on the paper. Copied onto each result when marking opens, so a later correction to the paper cannot silently rescale marks already given. |
| `weight_percent` | decimal | — | How much of the section's final grade this piece carries, as a percentage. The weights of a section's published assessments are expected to total 100, and the weighting report is what shows when they do not. |
| `due_on` | date | — | When the work is due in. The overdue-marking report measures from here, not from the date the assessment was set. |
| `status` | string | — | draft — being written, invisible to students; published — visible, result rows created for the group; marking — work is in and being marked; marked — every result is in and the grade contributes; cancelled — the piece will not count, and its results are ignored by the weighting. |
| `instructions` | text | OPTIONAL | What the students were told to do. Optional, and the only record of the task when a mark is queried a term later. |

## Cross-entity effects

Publishing an assessment is expected to create one result row per enrolled student. Not modelled as a saga: a `CreateEntity` step writes one row, and the fan-out over a group belongs in the application. Stated here rather than left as an assumption.
