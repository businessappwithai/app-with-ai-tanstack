# AdmissionApplication  ·  standalone  ·  category: Admissions

**Role.** A request for a place, with an outcome. Terminal once accepted, declined, rejected or withdrawn; the student record is created at acceptance.

**Placement.** Standalone. The admissions queue is the admissions officer's entire working screen.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `reference` | string | UK | The reference quoted in every letter to the family, e.g. APP-2026-0142. Unique, and the only identifier a family has before a student number exists. |
| `guardian_id` | string | FK | The adult who applied and who every decision letter goes to. Created before the application where the guardian is new to the school. |
| `student_id` | string | FK OPTIONAL | The student record created when the offer was accepted. Blank until then — this is the field that links an admission to the child it produced, and it is what makes the conversion report possible. |
| `academic_term_id` | string | FK | The term the place is applied for. An application for a term that has already started is a mid-year admission and is handled by the registrar rather than the intake process. |
| `decided_by_id` | string | FK OPTIONAL | The member of staff who made the decision and is accountable for it. Blank while the application is still open. |
| `applicant_first_name` | string | — | The child's given name as the family wrote it. Held on the application rather than taken from a student record, because no student record exists until the offer is accepted. |
| `applicant_last_name` | string | — | The child's family name, as written on the application. |
| `applicant_date_of_birth` | date | — | Used to check the child is of age for the year group applied for. A mismatch here is the most common reason an application goes to review rather than straight to an offer. |
| `year_group_applied_for` | integer | — | The teaching year the place is wanted in, 7 to 13. Entry to 12 and 13 carries subject requirements the interview checks. |
| `status` | string | — | submitted — received, nothing looked at; under_review — with an admissions officer; offer_made — the family has a letter and a deadline; accepted — the place is taken and the student record now exists; declined — the family said no; rejected — the school said no; withdrawn — the family pulled the application before a decision. |
| `submitted_on` | date | — | When the family applied. Intakes are worked in submission order where the band is equal, so this is a fairness field, not a timestamp. |
| `decided_on` | date | OPTIONAL | When the decision was recorded. The offer deadline is measured from it, and the gap between this and submitted_on is the response time the intake report is judged on. |
| `prior_attainment_score` | integer | OPTIONAL | The score from the previous school's report or the entrance paper, 0 to 100. Optional — an in-year transfer often arrives without one, and its absence sends the application to review rather than refusing it. |
| `has_sibling_enrolled` | boolean | — | Set where a brother or sister is already enrolled. Sibling priority is school policy, and this is the field the admission banding rule reads. |
| `admission_band` | string | OPTIONAL | priority — meets the attainment bar or carries sibling priority; standard — the ordinary offer queue; review — needs a person to look, because something is missing or borderline. Set by the admission banding rule on submission; an admissions officer may overwrite it, and the override is what the banding-override report shows. |
| `decision_notes` | text | OPTIONAL | Why the decision went the way it did, written for the family's file rather than for the assessor. Required in practice for a rejection, because it is what the appeal is answered from. |
| `under_review_at` | datetime | OPTIONAL | When the move to under review was recorded on this admission application. Recording it moves an admission application from submitted to under review: the workflows set the status, which nobody changes by hand. |
| `offer_made_at` | datetime | OPTIONAL | When the move to offer made was recorded on this admission application. Recording it moves an admission application from under review to offer made: the workflows set the status, which nobody changes by hand. |
| `rejected_at` | datetime | OPTIONAL | When the move to rejected was recorded on this admission application. Recording it moves an admission application from under review to rejected: the workflows set the status, which nobody changes by hand. |
| `accepted_at` | datetime | OPTIONAL | When the move to accepted was recorded on this admission application. Recording it moves an admission application from offer made to accepted: the workflows set the status, which nobody changes by hand. |
| `declined_at` | datetime | OPTIONAL | When the move to declined was recorded on this admission application. Recording it moves an admission application from offer made to declined: the workflows set the status, which nobody changes by hand. |
| `withdrawn_at` | datetime | OPTIONAL | When the move to withdrawn was recorded on this admission application. Recording it moves an admission application from submitted, under review or offer made to withdrawn: the workflows set the status, which nobody changes by hand. |

## Rules

### `admissionAssessment` on `beforeCreate` — **node graph — it decides only, and cannot act**

No outputs: the engine finds no actions, by design (§3.4).

### `admissionBanding` on `beforeCreate` — **`%%action` decision table — it can act**

- `bandOnSibling transform when: has_sibling_enrolled == true field: admission_band value: priority`
- `bandOnAttainment transform when: has_sibling_enrolled == false and prior_attainment_score >= 70 field: admission_band value: priority`
- `bandStandard transform when: has_sibling_enrolled == false and prior_attainment_score < 70 field: admission_band value: standard`
- `bandForReview transform when: prior_attainment_score == null field: admission_band value: review`
- `requireDecisionNotesOnRejection validation-error when: status == "rejected" and decision_notes == null message: A rejected application needs a note — it is what the appeal is answered from.`
- `requireDecisionNotesOnRejectionOnMove validation-error when: rejected_at != null and decision_notes == null message: A rejected application needs a note — it is what the appeal is answered from.`
- `enrolOnAcceptance trigger-workflow when: status == "accepted" workflow: AdmissionToEnrolment`

## Open questions

Whether an offer should expire automatically after its deadline. Not modelled: an expiry that runs unattended has told a family no, and the school wants a person to do that. `admissions-offers-unanswered` is the report that makes it a decision.
