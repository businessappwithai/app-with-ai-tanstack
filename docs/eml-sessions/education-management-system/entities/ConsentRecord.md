# ConsentRecord  ·  standalone  ·  category: Student Support

**Role.** One guardian's time-bounded decision about a student's participation, information use or emergency treatment. Withdrawal preserves the earlier authority and when it ended.

**Placement.** Standalone. The renewal queue — every consent that lapses in the next thirty days, across all students — is a list someone opens in its own right (`registrar-consents-expiring`), and a consent has its own identity: this guardian's decision about this student's participation, on a date.

## Fields

| Column | Type | Modifiers | Purpose |
|---|---|---|---|
| `id` | string | PK | The record's own identifier. Generated by the application and never keyed; it is never shown as a display value. |
| `student_id` | string | FK | The student whose participation or information use this decision governs. Consent is stored per student because siblings may have different decisions. |
| `guardian_id` | string | FK | The guardian who gave or withdrew the decision and whose authority must be verified before staff rely on it. |
| `consent_type` | string | — | The controlled purpose the guardian agreed to, so approval for a trip is never treated as approval for media use or data sharing. |
| `status` | string | — | draft — captured but not yet relied on; active — currently valid; withdrawn — revoked by the guardian; expired — passed its stated end date and must be renewed. |
| `effective_on` | date | — | The first date staff may rely on this consent. A future-dated decision remains draft until this day. |
| `expires_on` | date | OPTIONAL | The final day the consent remains valid where the purpose is time-bounded. Blank means it continues until withdrawal. |
| `withdrawn_at` | datetime | OPTIONAL | When the guardian revoked consent. Kept with the original record so earlier authorised activity remains explainable. |
| `withdrawal_reason` | text | OPTIONAL | The guardian's reason where they chose to give one. It is optional and must not be used to pressure a family to keep consent active. |
| `evidence_url` | string | OPTIONAL | A protected link to the signed form or verified digital evidence. Access must follow the same restrictions as the consent record. |

## Enums

- `consent_type` → **ConsentType**: medical_treatment, educational_trip, media_use, data_sharing, emergency_contact, digital_services
- `status` → **ConsentStatus**: draft, active, withdrawn, expired

## Relationships

- `Student ||--o{ ConsentRecord` — has consent *(this side carries the foreign key)*
- `Guardian ||--o{ ConsentRecord` — grants consent *(this side carries the foreign key)*

**Indexes.** `ConsentRecord(student_id, consent_type, status)`

## Rules

### `consentControl` on `beforeUpdate` — **`%%action` decision table — it can act**

- `requireConsentWithdrawalTime validation-error when: status == "withdrawn" and withdrawn_at == null message: Withdrawing consent requires the time authority ended so later activity cannot be mistaken for authorised activity.`

## Hooks

None.

## Cross-entity effects

None. Withdrawing a consent records when authority ended and does not stop anything by itself; no hook or saga reads `ConsentRecord`, so whoever acts on a trip, a photograph or a data share checks the record.

## Open questions

`expire` is a transition nobody triggers: like an invoice going overdue it is the clock's, so `registrar-consents-expiring` is the list a person acts from rather than a rule that fires. A guardian can read and withdraw consents through the `guardian` role, but `%%rbac` cannot scope that role to their own child — the same limitation `02-cross-cutting.md` records for every guardian-readable entity.
